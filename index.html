TECHNICKÝ NÁVRH v0.1 27. 7. 2026

Co je potřeba postavit

Pracovní rozpad systému pro sběr podkladů, výpočet hypotečního benchmarku a periodický report. Není to finální architektura ani odhad pracnosti.

Krátká verze

Jádro je běžná datová pipeline a relační databáze. AI je volitelný worker pro vytěžení strukturovaných faktů z textu. Benchmark samotný musí být deterministický kód, ne odpověď modelu.

STAVÍME

Datovou aplikaci

  • konektory na zdroje
  • inkrementální zpracování
  • verzovaná fakta a metriky
  • dashboard + report
NESTAVÍME

Vlastní AI model

  • trénování foundation modelu
  • chat nad celým archivem v MVP
  • real-time streaming
  • AI generované výsledné skóre
ZATÍM NEVÍME

Lokální podmínky

  • povolený přístup na internet
  • dostupný model a GPU
  • standardní OCP komponenty
  • konkrétní zdroje a ACL
01

Navržená architektura

Minimální počet komponent pro první použitelnou verzi.

→ → volitelně AI→ → →
INPUT

Zdroje a konektory

  • Každý typ zdroje má samostatný adaptér.
  • Konektor vrací obsah, metadata, ACL, source ID a čas změny.
  • Veřejný web musí jít vypnout bez dopadu na zbytek systému.
WORKER

Inkrementální ingest

  • Porovná source version nebo hash obsahu.
  • Originál uloží beze změny do object storage.
  • Nezměněné položky ukončí bez parsování a AI.
WORKER

Zpracování dokumentu

  • Parser podle MIME typu, čištění šumu a logické sekce.
  • Deduplikace podle hashe a podobnosti.
  • Neúspěšné položky skončí v karanténě s důvodem.
DATA

Strukturovaná fakta

  • Každý fakt má typ, hodnotu, platnost a vazbu na pasáž zdroje.
  • AI extrakce je pouze kandidát, dokud neprojde validací.
  • Přepis hodnoty vytváří novou verzi, nemaže historii.
CODE

Výpočet benchmarku

  • Vstupem jsou pouze validní strukturovaná fakta.
  • Metodika, váhy a verze výpočtu jsou uložené.
  • Stejný vstup a verze metodiky vždy dají stejný výsledek.
OUTPUT

Dashboard a report

  • Read-only API poskytuje KPI, trend a citované podklady.
  • Report skládá pouze změny od posledního období.
  • Publikace reportu má explicitní lidské schválení.

03

Kde přesně použít AI

AI worker je jeden krok pipeline. Systém musí fungovat i bez něj.

ANO

Úloha má pevný výstup

classify()

Zařadit dokument do existující taxonomie.

extract()

Vrátit kandidátní fakta podle JSON Schema.

compare()

Označit možné rozpory nebo změnu tvrzení.

summarize_delta()

Navrhnout komentář pouze nad dodanými změnami.

NE

Úloha nemá kontrolovatelný výstup

score_product()

Skóre musí vypočítat verzovaný kód.

remember_all()

Model neslouží jako úložiště znalostí.

read_everything()

Celý korpus se neposílá při každém běhu.

decide()

Model nevydává finální produktové rozhodnutí.

Kontrakt AI extrakce example 
{
  "fact_type": "competitor.time_to_offer",
  "subject": "bank_id",
  "value": 2.5,
  "unit": "day",
  "valid_at": "2026-07-01",
  "evidence": {
    "section_id": "sec_0183",
    "quote": "Nabídku obdržíte do 2,5 pracovního dne."
  },
  "confidence": 0.91
}
Důležité: validace schématu potvrzuje jen formát. Pravdivost se ověřuje pravidly, vazbou na citaci a případně člověkem.

05

Hranice prvního MVP

Nejmenší verze, na které lze ověřit, že benchmark vůbec dává smysl.

Vstupy

  • 2–3 typy zdrojů
  • stovky dokumentů, ne celý archiv
  • ruční import jako bezpečný fallback
  • jedna sada přístupových práv

Funkce

  • inkrementální ingest
  • historie verzí a citace
  • 10–20 metrik
  • trend proti minulému období

Výstup

  • jednoduchý interní dashboard
  • detail výpočtu každé metriky
  • stav a čerstvost zdrojů
  • export periodického reportu

Mimo MVP

  • chat a obecné dotazování
  • automatické produktové návrhy
  • real-time aktualizace
  • automatická publikace bez kontroly

Nasazení na OCP

Logické komponenty. Konkrétní produkty je potřeba sladit s lokálními standardy.

Frontendstatic build / web server

OpenSearchfulltext · lze odložit

Škálování

Na daný objem stačí batch joby s omezenou concurrency. Kafka ani Spark nejsou potřeba.

Tokeny

Hash + cache + uložené fakty. Model dostane pouze nový text, nikdy celý archiv.

Chyby

Retry pro dočasné chyby, karanténa pro vadný dokument, žádné tiché přeskočení.

Pozorovatelnost

Počet dokumentů, změn, chyb, doba běhu, tokeny a přesnost AI extrakce.
